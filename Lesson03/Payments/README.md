# Домашнє завдання 3. Ієрархія платежів (NVI, абстрактний клас, інтерфейс)

Консольна програма на C#, яка демонструє ієрархію платежів із чіткими інваріантами, шаблоном NVI і поліморфною обробкою через подію `Processed`.

## Як зібрати

Виконати в папці `Payments` (там, де лежить `Payments.csproj`):

```cmd
dotnet build
```

## Як запустити демо

```cmd
dotnet run
```

## Що очікувати в консолі

Програма обробляє три платежі по черзі, для кожного виводить рядок від самого платежу, а потім рядок від події `Processed`. Далі виконується повернення 200 UAH з картки і перевірка інваріантів.

| Крок | Очікуваний вивід |
| --- | --- |
| Готівка | `[Готівка] Прийнято 150.00 UAH.` і `-> подія Processed: CashPayment` |
| Картка | `[Картка **** 4242] Списано 500.00 UAH, код A1B2.` і `-> подія Processed: CardPayment` |
| Крипто | `[Крипто] Транзакція 0xabc123, сума 0.01 BTC.` і `-> подія Processed: CryptoPayment` |
| Повернення | `[Картка **** 4242] Повернено 200.00 UAH.` |
| Сума 0 | Виняток `ArgumentOutOfRangeException`, програма його перехоплює і виводить повідомлення |
| Порожня валюта | Виняток `ArgumentException`, програма його перехоплює і виводить повідомлення |
| ProcessedUtc | Дата і час обробки в UTC для готівки |

## Тести

Перевірка виконується через демо: сума 0, порожня валюта і повернення сумою більше сплаченої мають давати повідомлення про помилку, а не аварійне завершення.

## Структура коду

- `Payment` — абстрактна база. Містить спільні властивості (`Amount`, `Currency`, `CreatedUtc`, `ProcessedUtc`), публічний невіртуальний метод `Process()` і подію `Processed`.
- `CashPayment`, `CardPayment`, `CryptoPayment` — похідні типи, які перевизначають `DoProcess()`.
- `IRefundable` — інтерфейс повернення коштів. Реалізує лише `CardPayment`.
- `PaymentProcessedEventArgs` — аргументи події.

## Послідовність `Process()`

1. Валідація інваріантів.
2. `OnBeforeProcess()`
3. `DoProcess()`
4. `OnAfterProcess()`
5. `OnProcessed(e)`

## Прийняті рішення

- **Абстрактний клас `Payment`** обрано, бо всі платежі мають спільний стан і спільний порядок кроків.
- **Інтерфейс `IRefundable`** обрано, бо не всі платежі підтримують повернення. Так у `CashPayment` немає методу, який він не може виконати, і немає `NotSupportedException`.
- **NVI:** `Process()` невіртуальний, тому підклас не може змінити порядок кроків або обійти валідацію.
- **Події через `OnProcessed`:** подія піднімається в одному місці, а підклас може перевизначити цей метод, не викликаючи подію напряму.
- **`sealed`** у базовому варіанті не використав.
