# Відповіді на теоретичні питання (CW_03_Q)

## 1. Коли успадкування доречне?

Успадкування доречне, коли підтип справді є різновидом базового типу («є», наприклад `CardPayment` є `Payment`). Якщо потрібне лише повторне використання коду або підтип змінює суть поведінки, краще обрати композицію.

## 2. Що виведе програма?

```csharp
class Base { public virtual void M() => Console.WriteLine("Base"); }
class Der : Base { public override void M() => Console.WriteLine("Der"); }
Base x = new Der();
x.M();
```

**Відповідь:** `Der`.

## 3. Що виведе програма?

```csharp
class B { public void M() => Console.WriteLine("B"); }
class D : B { public new void M() => Console.WriteLine("D"); }
B a = new D();
D b = new D();
a.M();
b.M();
```

**Відповідь:**

```
B
D
```

`new` не є віртуальним. `a.M()` вибирає метод за статичним типом змінної (`B`), а `b.M()` — метод `D`.

## 4. Чому Save() у базовому Document робимо не virtual, а гачки protected virtual?

Це шаблон NVI. Публічний метод невіртуальний, тому порядок кроків і інваріанти фіксує база, і підклас не може їх обійти. Підкласи змінюють окремі кроки через захищені віртуальні гачки.

## 5. Чому не можна викликати віртуальний метод у конструкторі базового класу?

Конструктор базового класу виконується раніше за конструктор похідного. Якщо він викличе `override`, підклас ще не ініціалізував свої поля, і метод може працювати з порожніми або нульовими значеннями.

## 6. Що означає protected для члена базового класу?

Член доступний у самому класі та в його підкласах, але не ззовні. Це дає похідним класам доступ до внутрішньої логіки бази, не відкриваючи її всім.

## 7. Коли властивість варто робити virtual?

Коли підклас має змінювати спосіб отримання або зберігання значення, наприклад, обчислювати його інакше. Якщо значення просто зберігається, віртуальність не потрібна.

## 8. Чому подію піднімають через protected virtual OnXxx(e)?

Метод `OnXxx` є єдиним місцем виклику події. Його можна перевизначити в підкласі, а виклик безпечно перевіряє `null`. Підклас не може викликати подію напряму, тому не може випадково її зламати.

## 9. Коли обираємо інтерфейс замість абстрактного класу?

Коли контракт має реалізувати різні, непов'язані типи, або клас має реалізувати кілька контрактів. Абстрактний клас обирають, коли є спільний стан і спільний код, потрібні всім нащадкам.

## 10. Навіщо методи за замовчуванням в інтерфейсах?

Щоб додати новий метод до інтерфейсу, не ламаючи вже існуючі реалізації.

## 11. Чому рефакторинг Bird.Fly() → IFlyBehavior відновлює LSP?

Коли політ винесено в `IFlyBehavior`, можна використувати іншу реалізацію (наприклад, `NoFly`). Кожен тип виконує лише те, що може, і немає винятків у «нормальних» сценаріях.

## 12. Для чого у спадкуванні корисна рефлексія?

Рефлексія дозволяє знайти всі підтипи, перевірити їхні інтерфейси та визначити, які методи перевизначені (`override`).
